# Numbers — component reference

Generated by `python -m biblecore build` from the components this book enables in `book.json`. Don't edit. The style reference's section 4 lists the base components and any book-specific notes. Any unit may use any component listed here.


## echo — a verse-level cross-book echo ("cf.")

```html
<p class="v"><span class="n">3</span> …</p>
<aside class="echo" data-anchor="1:3">Deut 11:24 gave the same promise; Josh 1:3 repeats it almost word for word.</aside>
```

- It's a **following sibling** of the verse, like `.gloss`. Never nest it inside a gloss, and always close it.
- `data-anchor` is the verse it follows (`C:V`), and the build checks that it matches.
- The site prepends "cf." and collapses it into the verse's note toggle, so don't write "cf." yourself.
- Use it for a verse-level link. A single word's history goes in that root's `echo` field instead.
- Echo asides are harvested into `data/canon.json` automatically, so don't repeat them in `intertext[]`.

**What counts as verified:** you've read the target verse, and the link rests on shared words, a shared phrase or a recognised type-scene, not just a shared theme.


## list — a count or list table (census, roster, allotment)

```html
<section class="block">
  <h2>The first accounting <span class="cap">· 1:20–46</span></h2>
  <table class="list" data-verses="1:20–43">
    <thead><tr><th>Tribe</th><th>Counted</th></tr></thead>
    <tbody><tr><td>Reuven</td><td>46,500</td></tr></tbody>
    <tfoot><tr><td>All Israel</td><td>603,550</td></tr></tfoot>
  </table>
</section>
```

- It goes inside a `section.block`. Its first row is a header row of `<th>`, and every row has the same number of cells.
- The last column is the number, and it's right-aligned.
- A total the text itself gives goes in `<tfoot>`.
- It stays in line with the text; it isn't hoisted to the top with the structure blocks.
- Cells may carry `data-root` spans, tracked threads included. Inside a `data-verses` table these are summary tags: they colour the cell but stand for words in several verses, so they need no `data-w`, and the audit counts the declared verses as covered.
- `data-verses` names exactly the verses the table replaces, when it condenses a repeated formula. Say so in the pericope's gloss.

**What counts as verified:** every number and name comes from the verses. The table condenses the text; it doesn't add to it.


## poem — poetry set in lines (cola) inside ordinary verse blocks

```html
<div class="poem">
  <div class="v"><span class="n">24</span><span class="l">May Yahweh <span class="r" data-root="bless">bless</span> you</span><span class="l in">and keep you.</span></div>
  <span class="gloss">Three lines, each longer than the last …</span>
  <div class="v"><span class="n">25</span><span class="l">May Yahweh make his face shine on you</span><span class="l in">and be gracious to you.<sup class="en"><a href="#n4">4</a></sup></span></div>
</div>
```

- Poetry stays in **ordinary verse blocks** (`div.v`, one per verse), so tagging, `data-w`, the audit and verse links work exactly as in prose. The poem only sets the text in lines.
- Every word of a poem verse sits inside a `span.l` line; only the verse number and whitespace sit outside. Put the endnote marker at the end of the last line.
- Add `class="l in"` for an indented, continuing line (a second or third colon).
- Glosses and asides go between verses inside the `div.poem`, as they do in prose.
- `data-pair="A"` / `"B"` on lines is optional. Use it only when the parallelism is the point of a note.
- A `div.poem` never sits inside a `section.block`, and poems don't nest.
- A short poetic inset inside prose (a song, an oracle, a blessing) gets its own `div.poem` between the prose verses.

**What counts as verified:** line breaks follow the Masoretic accents (the major disjunctives, ʾatnaḥ first) or an established critical layout, not the English rhythm. Say which in a note when a break is debatable.


## itin — an itinerary as a row of stops (journeys, stations, campaigns)

```html
<section class="block">
  <h2>From Rameses to the plains of Moav <span class="cap">· 33:5–49</span></h2>
  <div class="itin" data-verses="33:5–49">
    <span class="stop">Rameses <sup>33:5</sup></span><span class="arr">→</span>
    <span class="stop">Sukkot <sup>33:5</sup></span><span class="arr">→</span>
    <span class="stop">Etam <sup>33:6</sup></span>
  </div>
</section>
```

- It goes inside a `section.block`, and it stays in line with the text.
- Its direct children are only `span.stop` and `span.arr` ("→"), alternating, starting and ending with a stop.
- A stop may carry a `data-root` span (a place name you're tracking) and a `<sup>` with its verse (`C:V`), or a range (`C:V–V`) when the stop is a whole scene.
- `data-verses` goes on the `div.itin` when the chips replace the verses (a formulaic station list). When the prose verses are also written out, leave it off and the chips are a summary. Tracked-thread spans inside a `data-verses` block need no `data-w` (summary tags, colour only).

**What counts as verified:** the stops and their order come from the verses. A route the text doesn't give (a scholar's reconstruction) belongs in a note, not in the chips.


## textform — a text-form note: where another witness (LXX, Samaritan, Qumran, Qere) reads differently

```html
<p class="v"><span class="n">4</span> …</p>
<aside class="textform" data-anchor="1:4" data-src="lxx">lacks “the whole land of the Hittites.”</aside>
```

- It's a **following sibling** of the verse, like `.gloss` and `aside.echo`, with the same rules: never nested, always closed, and `data-anchor` is the verse it follows.
- `data-src` names the witness: `mt`, `lxx`, `sp` (Samaritan), `dss` (Qumran), `qere`, `ketiv`, `targum`, `peshitta`, `vulgate`. The site prints the label, so start the text with what the witness reads or lacks.
- One aside per witness per verse. Keep it to a line, and put the argument about which reading is earlier in a footnote.
- Transliterate or translate. Never type Greek or Hebrew script.

**What counts as verified:** you've checked the witness itself (an edition, an apparatus, or the commentary on hand that cites it), not a secondhand summary. Say in a footnote which source it came from when it matters.


## story — an earlier story told beside a verse: a different, earlier event with the same shape, with its background, what's the same, what's different and what it does here

A verse sibling for a *different, earlier* event with the same shape, told
with its background: Herod's feast beside Pharaoh's birthday feast, Elisha's
loaves beside the wilderness meal. The same event told by another gospel (or
Chronicles beside Kings) is a `synoptic`, never a story box. A link one
sentence can carry is an `aside.echo`.

```html
<aside class="story" data-anchor="14:6" data-kind="type-scene" data-scene="royal-birthday-feast" data-strength="strong">
  <h4><span class="par-title">Pharaoh's birthday feast</span> <span class="par-ref">Gen 40:20–22</span></h4>
  <p class="par-story">Two to four plain sentences telling the earlier story.</p>
  <ul class="par-match"><li>what's the same</li><li>…</li></ul>
  <p class="par-diff">What's different.</p>
  <p class="par-does">What it does here: irony, reversal, identification, fulfilment, warning.</p>
  <p class="par-later">Later reuse, only if there is one.</p>
</aside>
```

- It follows the verse it bears on, or the last verse of the scene it covers;
  `data-anchor` must match that verse. `data-span="14:3–12"` is optional.
- `data-kind`: `type-scene`, `story`, `allusion`, `character` or `reuse`. A
  `type-scene` box also names its type-scene: `data-scene="<id>"`. Check the
  canon's type-scene list first; a new id is the book owner's call.
- `data-strength`: `strong` or `possible`; ship a `possible` link when it's
  worth Lane's eye, worded as tentative. A weak link never ships as a story
  box; it stays in the notes or becomes a footnote.
- Required: the `<h4>` with `par-title` and `par-ref`, then `par-story`,
  `par-diff` and `par-does`. **No box ships without a stated difference.**
  The `par-ref` must include verses, e.g. `Exod 24:15–18`; a bare chapter
  list like `Exod 24; 34` fails at build.
  `par-match` and `par-later` are optional.
- The site supplies the labels (Same, Different, What it does, Later), so
  don't write them. It hides each box behind its own ◈ chip, labelled
  "Type scene" for a type-scene and "Earlier story" otherwise.
- Transliteration only, and no `data-root`, `class="r"` or `class="rl"`
  inside (the occurrence scanner counts every `data-root`). When the box
  rests on shared words, put them in the box as evidence; don't also write
  an `aside.echo` for the same link. An argument about the link goes in a
  footnote; the box says only what the parallel is.
- Story boxes are harvested into `data/canon.json` (an intertext row per
  reference, a type-scene row for `data-scene`), so don't repeat them in
  `intertext[]` or `typescenes[]`.


## mirror — a passage of the mirrored book beside a verse: the twin text, the words the two share, and what the mirror shows here

For a book that declares a mirror in `book.json` (`mirrors`): a verse sibling
that sets the unit's passage beside its twin in the other book (Numbers 11
beside Exodus 18), with the words the two share. The pairing is a scholar's
reading, never a fact; say "one reading" in the prose if the box needs
qualifying. A link one sentence can carry is an `aside.echo`; the same event
told twice in the same book family is a `synoptic`; an unrelated earlier story
is a `story`.

```html
<aside class="mirror" data-anchor="11:14" data-pair="H" data-span="11:10–17">
  <h4><span class="par-title">The burden: too heavy … alone</span>
      <span class="par-ref">Exod 18:13–18</span>
      <span class="strength"></span></h4>
  <div class="row"><span class="src">Exod 18:18</span><span class="txt">… <span class="sh" data-ids="3515">heavy</span> … <span class="sh" data-ids="905">alone</span></span></div>
  <p class="take">What the mirror shows here.</p>
</aside>
```

- It follows the verse it bears on; `data-anchor` must match that verse and
  sit inside the pair's side of this book. `data-span` is optional.
- `data-pair` names a pair in the book's mirror data file (status `seed` or
  `kept`). **Boxes make no claim the data file doesn't hold:** the
  `par-ref` must lie inside the pair's twin passage, and every `span.sh`
  carries `data-ids` (Strong's, comma-separated) that the pair lists under
  `shared`. A word the pair doesn't list is not highlighted.
- Leave `span.strength` empty. The build writes the dots (and `data-n`) from
  the data file, so changing a strength there changes every box. An echo-tier
  pair has no strength span.
- One box per beat. A wide pair (several beats, several units) gets a box in
  each unit it touches, all with the same `data-pair`, each with its own
  `par-ref` inside the pair's twin passage.
- Translate the twin in the unit's own voice: the unit pack's mirror section
  has the Hebrew word order, transliteration and Strong's numbers, with a
  gloss only where the book already has one. **Never raise a strength above
  what the shared words support**, and don't ship a box for a link the data
  file does not hold; propose it in the meta block's `mirror[]` instead.
- A poetry twin (`poetry` in the pair) gets the header only: `par-title`,
  `par-ref`, `take`, no rows.
- `take` is required: one or two sentences on what the mirror shows here.
- Transliteration only, and no `data-root`, `class="r"` or `class="rl"`
  inside (the occurrence scanner counts every `data-root`).
- Mirror boxes are harvested into `data/canon.json` (an intertext row of kind
  `mirror` per reference in `par-ref`), so don't repeat them in `intertext[]`.
